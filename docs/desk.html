How it works

Designed, not yet running. Everything here is a sample.

Scripts do every step that can be code. A model is called only where a judgment has to be written down: one call, no tools, an answer in JSON that a script checks before anything moves.

Three models hold seats, one person signs, and a script publishes.

1The analyst

Writes the case for a call.

Reads
Facts and quoted filing excerpts that a script prepared. Never a price.
Writes
A memo: the thesis, what the market has wrong, a 3-month horizon, three risks and what would break the thesis.
Stops if
The memo fails a check, or can’t say what the market has wrong.

Can’t

3The chair

Decides whether a call that survived risk is worth publishing.

Reads
The memo with its dissent, the script’s eligibility check and the calls already open.
Writes
Publish or not, outperform or underperform, standard or high confidence, and an answer to the dissent.
Stops if
It declines. It can decline any call, but it can’t push one past the script’s check.
Limit
Up to 2 decisions a week.

Why fixed steps, and no agent

I chose fixed steps over an open-ended agent loop for three reasons. Filing text can carry a hidden instruction, and here it never reaches anything that can act. Each step has fixed inputs, so it can be tested case by case. And models are bad at arithmetic and at remembering rules, so both live in code.

Each seat runs as its own job. One script chaining all three calls would be one process pretending to be three, and a failure halfway would leave no clean status. Every run ends done, or waiting for me with the reason in the first line. An agent replaces a step only if a test fails because of the single-call shape.

Guardrails

The part that reads filings can’t act.

The rule I design against: nothing may hold all three of untrusted input, a secret and the ability to act outside the system. The seats read text derived from filings, but they have no tools, no secrets and nowhere to write except a draft. The publish script holds the write key, but it sees only validated fields. The plan runs it as a separate operating-system user whose key the seats’ user can’t read. I haven’t tested that on a real machine, and I won’t call it proven until I have.

A hidden instruction has five checks to get past.

Filing text enters a model’s input only as quoted data. A script scans it for instruction-like patterns before each call, and the model reports its own flag; either one marks the draft. Behind those, the schema rejects any field it doesn’t expect, the risk officer argues against the memo, and I read what would publish. A call publishes only if every seat and the scan report no injection.

Models answer in a fixed format, and a script checks every number.

Every answer has to parse against its JSON schema, and unknown fields are rejected. A script checks that each ticker and number appears in the input or is labeled an estimate with a method. Every claim is labeled sourced, estimated or unverified. A deny list blocks sizing, entry, stop, target and holdings language, and the schemas have no fields for any of it. The seats never see a price, only buckets a script computes.

A stopped idea stays private. A published call shows its reasoning.

Published, for a call I signed: ticker, outperform or underperform, horizon end, confidence, value range, benchmarks, the model behind each seat, a hash of the exact prompts, the package version, my approval id, the events that led to it, and whether it came from the schedule or my request. A separate reasoning file holds the thesis, pillars, falsifiers and the risk officer’s dissent, each length-capped and checked again before release.

Never published: the ticker of a vetoed or dropped idea, the memos and dissents behind it, full memos for any call, the prompts themselves (only their hash), position sizes, entry zones, stops, target prices, holdings, the restricted list, and anything from a proving run. Scores stay counts-only until the price feed’s terms allow returns.

The analyst can write a short note on a flagged anomaly, and if I pick “dig in”, it writes a full memo that enters the same path at the risk officer.

Every script that can call a model carries a daily model-call cap, 20 calls per day by default. Each call takes a slot before it runs, and a call that fails still counts. Anomaly notes get their own small lane, so a busy news week can’t starve the decision path. Over the cap, no call is made and the run comes to me listing what didn’t run. The Sunday digest prints calls against the cap.

Each seat runs as its own routine with its own work item, cap slot and final status. Each unit of work has one tracked item with a fixed name, such as the week plus the ticker. A retry or a re-fired routine finds that item and never spends a second slot on the same work.

An answer that fails a check is withheld and comes to me with the failed check named. A cap hit, a timeout, bad JSON, a failed check and a crash all land on my desk the same way.

All of these numbers are untested starting values. Proving will tune them.

The fixed checks must pass every case, every run: the output parses, every ticker and number is in the input, claims are labeled, the dissent isn’t empty, and there’s no sizing or entry language.

Quality is scored per pass, over 3 passes. Any safety failure restarts all 3. A model judge grades tone only, never a must or must-not check.

Three more desk-wide tests: restricted tickers must be blocked at the pull and again at publish, schema checks must reject any edit to an existing call, and the event feed must reject a ticker in any pre-publication event.

Run 3 times each, a pass is 555 model calls: the 145 Sonnet cases times 3, about 10 injection reruns times 3, and the chair’s 30 Opus cases times 3. Activating a seat takes at least 3 passes, so at least 1,665 calls, under their own cap and spread over days.

Asking the desk for a specific name

I can ask the desk to look at one ticker in a private channel. The request is a ticker and nothing else. The script rejects anything more, so I can’t hand over a thesis, a direction or a reason, and the chair can’t anchor on the boss.

The same checks apply. The name must be in that night’s universe and off the restricted list. If not, no call is made and the run comes back to me with the failed check named. The publish script checks both again.

A name that falls inside the publication window for my own private holdings is held, not called. I confirm privately that this conflict check covers my own obligations before the desk goes public.

There is no shortcut. The memo goes through the risk officer, the chair and my signature like any other, and a veto ends it the same way. No seat’s input says a memo was requested, so the seats never know.

The publish script sets an origin field on every call: schedule or request. No seat sets it. Each request also logs a ticker-less request.made event in the Sunday batch, so you can count my requests against the calls they produced and split the record by origin.

Requests are capped at 2 a week, and a second request for the same name in the same week spends nothing.

Five more roles could join the three model seats. None has one. Scripts and the analyst cover their work until one earns a seat: two clean runs, its own tests and a written decision. The ceiling is five seats.

The order the seats switch on

One at a time, so a bad memo format can’t cascade through two untested seats. Each step has to pass its check before the next seat can depend on it.

  1. The scorer and the ledger checks come first. The scorer must pass its holiday, split, dividend, delisting and ticker-change tests, and the ledger checks must reject every planted bad entry.
  2. Then the analyst: two clean scheduled runs at the proving cadence, one at the real cadence, and its tests at the bar.
  3. Then the risk officer: the same, plus a memo with a deliberate flaw that must draw a veto.
  4. Then the chair: the same, plus the approval test at 100%.
  5. Going public comes last: every start-build trigger box checked and the cutover dated in writing. The public ledger starts at No. 1 (C-1), with no proving calls carried over.
